# מחוץ למחנה

חדר בריחה מקוון לשני שחקנים על טהרת המצורע. החבילה כוללת את החדר הראשון, "מחוץ לחומה", ושרת שמגיש את המשחק ומסנכרן בין השחקנים. התכנון המלא של כל המשחק נמצא ב־[DESIGN.md](DESIGN.md).

## הפעלה מהירה

צריך Node.js בגרסה 18 ומעלה. לשרת אין תלויות חיצוניות.

```
npm start
```

פותחים בדפדפן את `http://localhost:8080`. השחקן השני נכנס לאותה כתובת ומצטרף עם קוד החדר.

המשחק כבר בנוי בתיקייה `dist`. בנייה מחדש נדרשת רק אחרי שינוי בקוד:

```
npm install
npm run build
```

## העלאה לשרת

יש שלוש דרכים, לפי מה שיש לך:

1. **שרת עם Node.js.** מעתיקים את התיקייה, למשל ל־`/opt/machane`, ומריצים `npm start`. להפעלה קבועה יש דוגמת שירות systemd בקובץ `deploy/machane.service`.
2. **Docker.** בונים עם `docker build -t machane .` ומריצים עם `docker run -p 8080:8080 -v machane-data:/data machane`. את הקובץ הזה עוד לא בדקתי בפועל, כי בסביבה שבה נבנה המשחק לא רץ Docker.
3. **שירות אירוח כמו Render, Railway או Fly.io.** מגדירים פקודת בנייה `npm install && npm run build` ופקודת הפעלה `npm start`. השרת קורא את הפורט ממשתנה הסביבה `PORT`.

אם יש nginx לפני השרת, צריך לכבות buffering בנתיב `/api/`, אחרת העדכונים בזמן אמת יתעכבו. בקובץ `deploy/nginx.conf` יש דוגמה מוכנה. מומלץ להגיש את האתר ב־HTTPS.

### משתני סביבה

| משתנה | ברירת מחדל | תפקיד |
|---|---|---|
| `PORT` | 8080 | הפורט שהשרת מאזין בו |
| `DATA_DIR` | `./data` | התיקייה שבה נשמרים החדרים |
| `ROOM_TTL_HOURS` | 48 | אחרי כמה שעות בלי פעילות חדר נמחק |

## איך הסנכרון עובד

- **מצב החדר:** כל חדר הוא מסמך JSON אחד בזיכרון השרת, ונשמר לקובץ `data/games.json`.
- **פעולות:** כל פעולה של שחקן נשלחת לשרת כתיקון קטן למסמך.
- **עדכונים:** השרת מעדכן מיד את שני השחקנים בערוץ Server-Sent Events. אין צורך ב־WebSocket.
- **בחירת הסנכרון:** הלקוח בוחר אותה לבד. כשהמשחק רץ מהשרת הזה, הוא מסתנכרן דרכו. בקישור של claude.ai הוא משתמש במסד הנתונים של הקישור. בקובץ שנפתח ישירות מהמחשב הוא מסתנכרן רק בין לשוניות של אותו דפדפן.

### ה־API של השרת

| בקשה | תפקיד |
|---|---|
| `GET /api/health` | בדיקה שהשרת חי |
| `GET /api/games/:code` | מצב החדר |
| `POST /api/games/:code` | פתיחת חדר חדש |
| `POST /api/games/:code/patch` | עדכון חלקי של מצב החדר |
| `GET /api/games/:code/events` | ערוץ העדכונים בזמן אמת |

## מבנה הקוד

| קובץ | תפקיד |
|---|---|
| `src/content.js` | כל התוכן: מקומות, נגעים, פריטים, דפי הספר ומקורות. כאן עובר הבודק ההלכתי |
| `src/logic.js` | חוקי המשחק כפונקציות טהורות, בלי ממשק |
| `src/net.js` | שלוש דרכי הסנכרון: השרת, הקישור של claude.ai ולשוניות מקומיות |
| `src/main.js` | מסך הפתיחה, מעטפת המשחק, הניווט והשכבות |
| `src/art/` | הפנורמה, הסצנות הקרובות, ציורי הפריטים, הטקסטורות והתאורה לפי השעה |
| `src/ui/` | הספר, הבדיקה, השוק והמעיין |
| `src/styles.css` | העיצוב |
| `server/server.mjs` | השרת |
| `build.mjs`, `template.html` | הבנייה לקובץ אחד |
| `deploy/` | דוגמאות ל־nginx ול־systemd |

## הכרעות הלכתיות

- **מראות הנגעים:** כחכמים וכרמב"ם. שאת כצמר לבן, ותולדתה כקרום ביצה.
- **שעות הראייה:** כרבי יהודה, ארבע, חמש, שמונה ותשע. עוד לא אומת ברמב"ם עצמו.
- **לבירור:** הסעיפים המסומנים "לבירור" בטבלת המקורות ב־DESIGN.md עדיין צריכים בדיקה של תלמיד חכם.

## הצעדים הבאים

1. **השרת כסמכות.** היום הלקוח מחשב כל פעולה ושולח לשרת את התוצאה, והתשובות נמצאות בקוד שמגיע לדפדפן. הצעד הבא: הלקוח ישלח לשרת את הפעולה עצמה, השרת יריץ את `src/logic.js` וישלח לכל שחקן רק את מה שמותר לו לראות.
2. **החדר השני.** סדר הטהרה עצמו: השחיטה, ההזאה ושילוח הצפור.
3. **בדיקה הלכתית** של `src/content.js`.

## בדיקה לבד

פותחים את הכתובת בשני חלונות, ופותחים חדר באחד ומצטרפים אליו בשני. בכל חלון בוחרים תפקיד אחר, ומסדרים את החלונות זה לצד זה.
